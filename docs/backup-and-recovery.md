# TGCloud 备份与恢复

## 备份范围

在主菜单“13. 数据备份管理”操作：

| 操作 |
| --- |
| 1. 查看历史备份 |
| 2. 创建实例快照 |
| 3. 校验实例快照 |
| 4. 创建代理备份 |
| 5. 查看代理备份 |
| 6. 校验代理备份 |
| 7. 清理代理备份 |
| 0. 返回主菜单 |

实例快照保存配置、SQLite 业务数据库、Bot Session、个人监听 Session、rclone 和 CloudDrive2 授权配置，以及校验所需的程序来源信息。快照时短暂停止所选 Bot 和网关，使用 SQLite 一致性备份，再按结果恢复服务状态。

云端内容、`downloads/`、日志、共享代理和附加功能状态不属于实例快照的全部覆盖范围。代理证书与配置单独备份；重要云端文件、附加功能数据和下载现场需另行保存。不要递归归档 `clouddrive/mounts/`。

## 校验与演练

备份必须放在私有目录，包含凭据或 Session 的文件按秘密保护。校验确认清单、哈希、目录和数据库完整性；隔离恢复演练会在临时副本中打开数据库并检查任务恢复，不连接 Telegram、不启动网关，也不加载 Session。

隔离演练不等于生产恢复。保留原始备份；未通过校验的材料不覆盖运行目录。

## 生产恢复

先暂停新任务并停止 Bot，核对快照来源、当前版本和目录归属，独立保存现有数据，再按快照覆盖范围恢复经过验证的配置和数据。确认权限、数据库、Session、网关挂载与就绪状态后，仅启动一个 Bot 实例。

当前没有自动覆盖生产实例的一键恢复命令。目录或数据库身份不明确时停止，避免生成空库、合并两个数据库或同时使用相同 Session。

## 保留与清理

默认受管备份目录为 `/opt/tgcloud-backups`；独立导出目录由操作时明确选择。将重要副本保存在卸载范围之外。`prune-backups 1～50` 仅清理已核对范围的备份，执行前确认保留数量。

恢复后先核对[配置](configuration-guide.md)，再按 [Bot 指南](bot-guide.md)执行小文件验证。
