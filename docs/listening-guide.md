# TGCloud 监听与来源筛选

## 账号授权

监听默认关闭。管理员在自己的私有终端打开 `sudo tgcloud` → “3. 业务功能设置 → 2. 监听转存管理”，登录个人 Telegram 账号。个人监听 Session 与 Bot Session 独立保存；验证码、二次验证密码和 Session 都是敏感授权。

独立 Compose 的 `sudo bash manage.sh` 提供相同管理菜单。先保持 Bot 的普通文件转存可用，再添加监听来源。

## 来源、筛选与计划

通过 Bot 的监听界面添加当前账号可访问的频道或群组，核对来源和目标目录，再启用来源。按界面设置文件类型、标题／说明、大小等支持的筛选条件，以及来源命名和目录规则。

自动监听处理已启用来源的新消息。需要扫描既有消息时，使用界面的预览和转存计划，核对来源范围、命名、目标和数量后确认；不会默认抓取全部消息。审批与确认仍受管理员／来源权限和任务配额约束。

## 停用与故障

源码宿主入口：

```bash
python3 -B scripts/run_source.py listen status
python3 -B scripts/run_source.py listen disable
```

实际实例由目录及来源校验确定；自定义目录可使用 `--install-dir`。停用保留任务、来源和授权文件。账号冷却、FloodWait、权限撤销及消息不可访问会停止或退让相应操作，不能靠删除 Session 绕过。

监听不能突破 Telegram 服务端权限和下载限制。只处理自己有权访问、保存的内容。
