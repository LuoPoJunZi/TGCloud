# TGCloud Bot 与转存任务

## 首次转存

安装完成并通过 WebDAV 验收后，管理员私聊 Bot，发送或转发自己有权保存的文件。Bot 识别媒体、生成任务并排队，下载或流式传输后写入 CloudDrive2，并对远端大小复验。

先测试一个小文件，用任务详情核对状态，并在云盘官方客户端确认。Telegram 无法读取的消息、服务端限制或失效授权会按错误处理；不要反复提交同一文件掩盖问题。

## 原生命令菜单

```text
/status 查看系统状态
/queue 查看最近任务
/pause 暂停任务调度
/resume 恢复任务调度
/doctor 运行系统诊断
/orphans 检查临时文件
/help 查看使用帮助
```

## 任务与恢复操作

| 命令 | 用途 |
| --- | --- |
| `/tasks` | 打开任务操作入口 |
| `/task 编号` | 查看任务详情 |
| `/search 关键词` | 搜索自己的任务 |
| `/cancel 编号` | 请求取消任务 |
| `/retry 编号` | 按失败状态重新尝试 |
| `/restart 编号` | 确认后从头重传 |
| `/recover 编号` | 确认后保留原文件并换名恢复 |
| `/stream 编号` | 申请流式转存 |
| `/orphans` | 检查临时孤立文件，清理前确认 |

优先按 Bot 按钮与确认提示操作。重复消息、媒体身份和远端冲突由任务／目标检查处理；这不是跨网盘的内容哈希去重服务。对身份不确定、上传中断或远端重名的任务，先检查云端现场，再选择恢复动作。

## 管理员和成员

管理员由安装时的 `ALLOWED_USER_ID` 指定。使用 `sudo tgcloud` → “5. Bot 用户管理”授权、停用成员和设置可用配额。成员只能查看、搜索和操作自己的任务；系统级服务和授权操作由管理员控制。

## 分类、命名与监听

管理菜单“8. 文件分类设置”控制分类。命名规则与说明文字处理见[分类与命名](naming-guide.md)。监听默认关闭，个人账号授权与来源筛选见[监听指南](listening-guide.md)。

## 大文件与诊断

超过本地暂存预算的任务可申请流式传输。流式模式采用背压与资源窗口，仍需要可用内存、来源权限和健康目的端。`/doctor` 显示资源及目的端检查时间；界面刷新不会绕过服务端冷却。

网关接收和大小复验不代表内容哈希一致或云盘最终入库。保留重要文件的独立副本。
