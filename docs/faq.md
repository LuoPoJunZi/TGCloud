# TGCloud 常见问题

## 为什么单独运行安装脚本失败

在干净目录单独运行 `install.sh` 会进入在线引导模式，需要 `root` 终端、`curl` 与 Python 3.10+ 才能自动下载并校验正式源码包。如果当前目录存在残缺的本地源码（例如只复制了部分 `src/tgcloud/` 或 `scripts/`），安装入口会主动拦截以防混用；请换到空目录运行在线入口，或使用完整源码目录运行 `sudo bash install.sh`。

## 如何访问 CloudDrive2 后台

默认仅绑定主机回环端口 19798。使用 SSH 隧道、受控内网入口或 HTTPS 向导；不要直接把未经保护的管理 HTTP 开放到公网。

## Bot 在线但文件未上传

检查 `/doctor` 的时间、资源和目的目录状态，再从管理菜单运行就绪检查与 WebDAV 验收。确认云挂载、专用用户、目标目录和磁盘余量；不要只看容器健康。

## 为什么看起来已经上传却没有完成

任务可能仍在远端大小复验、等待资源、退让或错误恢复。查看单个任务与脱敏日志。网关接收和大小复验不能代表云盘官方最终入库。

## 文件名为什么没有采用说明文字

可读原名优先保留，说明文字只有通过规则检查才参与补全。运行 `naming-preview` 查看理由；规则评分不是 AI 置信度。

## WebDAV 返回 401 或 429 怎么办

HTTP 401 表示认证未通过，核对专用用户、密码、WebDAV 地址和权限。HTTP 429 表示服务端限流，等待退让窗口并降低请求压力；刷新界面不会绕过冷却。先保留具体错误和任务状态，避免连续重试。

## SSH 主机密钥提示变化怎么办

先确认连接的是自己的主机并核对新的主机指纹，再按 SSH 工具流程处理 `known_hosts`。不要通过关闭主机密钥核验来掩盖地址或主机异常。

## 监听为什么不立即处理所有消息

监听默认关闭，需要个人账号授权、有效来源及筛选规则。新消息监听和显式历史扫描分别处理；权限、冷却和配额都会影响计划，不会默认抓取全部内容。

## 数据库身份检查失败怎么办

停止服务变更，保留数据库及旁文件、日志和独立备份，核对实际目录。不要创建空库、手工合并数据库或删除 Session 来消除错误。

## 可以在 Windows 生产部署吗

宿主受管部署面向原生 Linux AMD64／ARM64。Windows 可编辑源码、运行适用的回归和生成部署包；FUSE、权限、PTY 和真实 Docker 检查需要相应环境。
