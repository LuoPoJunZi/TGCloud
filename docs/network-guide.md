# TGCloud HTTPS 与 WebDAV

## 网关管理

CloudDrive2 管理 HTTP 默认绑定 `127.0.0.1:19798`。可使用[安装指南](install.md)中的 SSH 隧道，或配置经过认证的 HTTPS 管理入口；可信内网可通过 LAN 向导选择访问地址。

Bot 的 WebDAV 连接使用专用写入用户。运行管理菜单“4. 健康检查诊断 → 2. 远端写入验收”前先完成云挂载；该操作会在授权后写入、复验并清理随机测试文件。

## HTTPS 反向代理

准备自己的域名，将 A／AAAA 记录指向主机，并确认 80／443 端口、DNS 和现有代理归属。使用 `sudo tgcloud` → “2. 访问入口管理 → 1. HTTPS 代理与证书”配置、检查或进行证书续期演练。

支持受管 Nginx／Certbot，以及明确授权复用已有 Docker Nginx。复用模式会核对容器、挂载和站点文件；冲突、归属不明或未恢复的事务会停止操作。独立 Compose 使用包内 HTTPS 管理工具及菜单，不混用脚本部署的卸载器。

仅解析 DNS 的配置更适合向导检查；使用其他代理或端口转发时，应先核对实际访问链路，不重复创建占用相同端口的代理。

## 外部只读 WebDAV

使用主菜单“2. 访问入口管理 → 3. 外部 WebDAV 管理”，为受限目录创建独立只读用户。与 Bot 写入用户分开，确认 CloudDrive2 当前版本和账户权限支持关闭上传、删除、移动、改名和管理权限后，再启用 HTTPS 路由。

工具会核对专用账号、用户目录和读取权限，并提供 HEAD／OPTIONS／Range 等读取验收。密码更换、停用和卸载通过同一管理入口处理。依赖仍存在时，不直接删除共享代理或网关。

## 排查顺序

先确认网关本机可达与云挂载正常，再核对 WebDAV 账号和目录，最后检查 DNS、证书、代理路由及公网访问。证书有效不等于 Bot 能成功转存；各项检查分别核对。
