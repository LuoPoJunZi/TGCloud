## TG2Cloud v1.5.9

本版修复下载长期无进度却持续占用名额、业务就绪误报和排队原因不明确的问题。一键脚本与独立 Docker Compose 共用修复后的 Bot 核心，保留各自安装、升级和管理方式。

## 本次修复

- 普通下载及流式取源在连续 300 秒没有有效字节推进时取消本次读取，等旧协程真正退出后，按原有次数限制重试。它不是整个文件的下载时限，正常慢速大文件不受总时长限制。
- 保留监听客户端明确的有限冷却和流式写入背压；重复进度不延长计时。重复取消不会拆散旧任务清理，无法退出时保留名额并告警，避免两个协程同时写同一文件。
- 下载停滞时业务就绪不再显示通过，诊断分别显示等待下载名额、等待停滞下载回收，并保留原有重试、配额、预算与磁盘原因。诊断只输出聚合数量和时间。
- 新增无进度、慢速、冷却、背压、取消回收、后续调度、两网关远端保留与旧快照兼容回归；加入原 v1.5.8 不可变提交的升级基线。

## 升级与数据兼容

业务 schema 3 不变，无数据库迁移、新运行依赖或新增安装参数。保留配置、任务、下载、Bot Session 和个人监听 Session；CloudDrive2 与 OpenList 的提交、不确定结果处理、去重及恢复策略不变。网关与代理固定镜像没有更新。

一键脚本使用原公网或内网入口，明确选择 v1.5.9；独立 Compose 核验同版完整部署包后，通过 manage.sh 的安装与升级操作更新，不能只替换单个脚本或混合部署方式。升级前做私密一致性备份；旧实例已卡住时先暂停新增任务并记录现场，再核对活动任务处理和备份，不通过删除数据库或 Session 解围。

回退前先停止新 Bot、保护当前数据，再按匹配的代码、配置和数据库快照操作，不同时启动使用同一 Token 的两个实例。流式异常继续保留远端现场，不自动删除未知云端文件。
